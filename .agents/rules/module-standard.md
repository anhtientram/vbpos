# Module standard

Every feature follows the sample module layout:

```text
lib/domains/entities/<module>/<module>_entities.dart
lib/domains/repositories/<module>/<module>_repository.dart
lib/domains/usecases/<module>/<action>_<module>_usecase.dart
lib/data/data_source/remote/<module>/<module>_api.dart
lib/data/data_source/remote/<module>/<module>_remote_data_source.dart
lib/data/models/request/<module>/<module>_request.dart
lib/data/models/response/<module>/<module>_response.dart
lib/data/mapper/<module>/<module>_mapper.dart
lib/data/repositories/<module>/<module>_repository_impl.dart
lib/presentations/pages/<module>/<module>_screen.dart
lib/presentations/pages/<module>/components/<module>_view.dart
lib/presentations/pages/<module>/cubit/<module>_cubit.dart
lib/presentations/pages/<module>/cubit/<module>_state.dart
lib/presentations/pages/<module>/models/<module>_model.dart
lib/presentations/pages/<module>/models/<module>_presentations_mapper.dart
```

Rules:

- Domain inputs are `XxxParams`; domain data types are `XxxEntities`.
- API request/response classes are DTOs under `data/` and use `toJson`/
  `fromJson` generated by `json_serializable`.
- Retrofit interfaces are annotated with `@RestApi()` and their `.g.dart` file
  is generated by `dart run build_runner build`.
- Repository and use case methods return `AsyncEither<T>` or
  `Future<Either<Failure, T>>`. Use `left(failure)` and `right(value)`.
- A data source catches transport/serialization errors and returns `left`; it
  must not throw a user-facing exception or return `null` for failure.
- Mappers are pure and have no Dio, Flutter, or localization imports.
- Do not add `Entity` classes or `_entity.dart` files.
- The module must remain independently testable with a fake repository.
